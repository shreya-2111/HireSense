1. EXECUTIVE SUMMARY & HIGH-LEVEL ELEVATOR PITCH
================================================================================
HireSense is an enterprise-grade AI-assisted Recruitment and Candidate Screening 
Platform. It empowers talent acquisition teams and recruiters to:
- Create, manage, and publish job postings with structured skill requirements.
- Ingest and parse resumes in PDF, DOCX, TXT, or scanned image formats via 
  a hybrid text-extraction + OCR pipeline.
- Automatically calculate multi-factor Match Scores between candidate resumes 
  and job descriptions (Skill Match + Experience Match + Domain Weighting).
- Generate intelligent, role-tailored technical & behavioral interview questions 
  using Google Gemini AI (with a zero-downtime deterministic fallback engine).
- Schedule candidate interviews, manage pipeline stages (Applied -> Screened -> 
  Shortlisted -> Interview -> Hired/Rejected), and track recruitment metrics with 
  live dynamic analytics and CSV reporting.

END-TO-END USER JOURNEYS (HOW THE APP WORKS IN PRODUCTION):
--------------------------------------------------------------------------------
Journey 1: Recruiter Registration & Authentication
1. Recruiter registers on `/register` or logs in on `/login`.
2. Backend verifies bcrypt password hash and generates a signed JWT Access Token.
3. Frontend stores JWT in localStorage/sessionStorage and initializes `RecruitmentContext`.
4. Global layout renders with authenticated navigation, personalized recruiter profile, and custom HireSense branding.

Journey 2: Job Creation
1. Recruiter navigates to `/jobs/create` and fills title, department, experience range, salary, and required skills (e.g. React, Node.js, Docker).
2. Request hits `POST /api/v1/jobs`.
3. SQLAlchemy stores Job in `jobs` table and associates normalized skills in `job_skills`.
4. The job is immediately available in the dashboard and candidate matching dropdowns.

Journey 3: Resume Screening & AI Analysis
1. Recruiter goes to `/resume-analyzer` or clicks "Screen Resume" on a candidate.
2. Recruiter uploads a resume (PDF/TXT) and selects the target Job Opening.
3. Frontend sends `multipart/form-data` to `POST /api/v1/analyze-resume`.
4. `file_parser.py` executes:
   - Level 1: Native text extraction using `pdfplumber` and `PyPDF2`.
   - Level 2 (if native text is empty/scanned): Rasterizes PDF pages into images via `pdf2image` and runs OCR via `pytesseract`.
5. `scoring.py` evaluates candidate skills against job requirements:
   - Matches mandatory and bonus skills.
   - Calculates Experience Fit (years vs required range).
   - Generates overall percentage Match Score (0 - 100%).
6. `gemini_service.py` sends the resume context + job requirements to Google Gemini:
   - Generates a tailored candidate summary, identified strengths, skill gaps, and custom technical interview questions.
   - If Gemini API is rate-limited (429) or offline, HireSense seamlessly activates its rule-based heuristic question engine with zero failure.
7. Candidate profile and match analysis are persisted in the database and displayed on screen in real time.

Journey 4: Interview Scheduling & Pipeline Management
1. Recruiter shortlists candidate and clicks "Schedule Interview".
2. Sets date, time slot, duration, interview type, and assigns interviewer.
3. Backend creates interview in `interviews` table, updates candidate status to "Interview Scheduled", and generates internal meeting links.
4. Dashboard and Interviews tab immediately reflect upcoming sessions with countdowns and quick-prep question studio drawer.

Journey 5: Live Analytics & Reporting
1. Recruiter opens `/analytics` tab.
2. Backend calculates real-time aggregation across MySQL tables: total applications, average match score, department hiring spread, score distributions, and candidate funnel.
3. Recruiter can export complete candidate pipelines to CSV format with a single click.

5. DETAILED ALGORITHMIC & TECHNICAL WORKFLOWS
================================================================================

--------------------------------------------------------------------------------
5.1 RESUME EXTRACTION PIPELINE (`file_parser.py`)
--------------------------------------------------------------------------------
When a recruiter uploads a resume:
1. File Identification: Inspects MIME type and file extension (.pdf, .docx, .txt).
2. Direct Text Extraction:
   - For PDFs: Uses `pdfplumber` to extract words, preserving layout.
   - For DOCX: Uses `python-docx` to extract paragraphs and tables.
   - For TXT: Decodes UTF-8 text directly.
3. OCR Scanned Detection: If extracted text contains fewer than 40 characters (indicating a scanned image or photo PDF), the system triggers the OCR fallback.
4. OCR Execution: Uses `pdf2image` to rasterize PDF pages at 300 DPI, then executes `pytesseract.image_to_string()` with text cleaning.
5. Normalization: Removes null bytes, normalizes whitespace, and structures text for matching.

--------------------------------------------------------------------------------
5.2 ALGORITHMIC CANDIDATE-JOB SCORING ENGINE (`scoring.py`)
--------------------------------------------------------------------------------
The Match Score (0 - 100%) is calculated through a multi-factor formula:

    Final Score = (Skill Score × 0.70) + (Experience Score × 0.20) + (Context Score × 0.10)

1. Skill Score (70% weight):
   - Compares extracted candidate skills against Job Required Skills using exact + synonym mapping (e.g., "ReactJS" = "React", "K8s" = "Kubernetes").
   - Mandatory skills carry higher weight than optional/nice-to-have skills.
   - Skill Match % = (Matched Skill Weights / Total Required Skill Weights) × 100.

2. Experience Score (20% weight):
   - Compares candidate's years of experience with job's minimum/maximum range.
   - If candidate experience >= job minimum: 100%.
   - If candidate experience < job minimum: Soft penalty curve based on the gap (e.g., 2 yrs vs 3 yrs required yields 75%).

3. Context & Education Score (10% weight):
   - Evaluates degree relevance (B.Tech, M.S., B.S. in Computer Science/Engineering) and domain keyword density.

--------------------------------------------------------------------------------
5.3 GOOGLE GEMINI AI INTEGRATION & FALLBACK SYSTEM (`gemini_service.py`)
--------------------------------------------------------------------------------
1. Prompt Construction: Formats candidate resume summary, job title, matched skills, and missing skills into a structured JSON instruction prompt.
2. Model Invocation: Calls Google Gemini API (`gemini-1.5-flash` or `gemini-3.6-flash`).
3. Output Validation: Enforces structured JSON response containing:
   - `summary`: Concise 2-sentence candidate overview.
   - `strengths`: Top 3 technical competencies observed.
   - `gaps`: Identified missing requirements.
   - `questions`: Array of 5 tailored interview questions categorized by type (Technical, Scenario, Behavioral) and difficulty (Easy, Medium, Hard).
4. Deterministic Rule-Based Fallback: If the Gemini API reaches its rate limit (HTTP 429), has no network connection, or fails:
   - HireSense automatically invokes its internal question engine.
   - Generates questions dynamically targeted at the candidate's specific matched and missing skills.
   - The user never experiences an error or crash.

--------------------------------------------------------------------------------
5.4 AUTHENTICATION & JWT SECURITY WORKFLOW (`security.py` + `auth_service.py`)
--------------------------------------------------------------------------------
1. Password Hashing: When a user registers or logs in, passwords are never stored in plain text. Passlib bcrypt applies standard 12-round salt hashing.
2. Token Creation: On successful login, the backend generates an HMAC-SHA256 signed JSON Web Token (JWT) with user ID, email, and expiration time (default: 24 hours).
3. Authorization Guard: Protected endpoints declare `current_user: User = Depends(get_current_user)`.
4. Token Verification: The dependency extracts the Bearer token from the `Authorization` header, decodes and verifies the cryptographic signature, and loads the active user from the database.

6. KEY INTERVIEW QUESTIONS & ANSWERS (DESIGNED FOR YOUR INTERVIEW)
================================================================================

Q1: "Can you give a 1-minute overview of HireSense?"
A1: "HireSense is an AI-powered recruitment management platform designed to automate and streamline candidate resume screening. It ingests resumes in any format—including scanned PDFs via OCR—scores candidate compatibility against job openings using a multi-factor matching algorithm, and leverages Google Gemini AI to generate tailored technical interview questions. Recruiters can manage the full pipeline, schedule interviews, and view live recruitment analytics."

Q2: "What is your tech stack and why did you choose it?"
A2: "For the backend, I chose FastAPI with Python 3.11 for its async speed, automatic OpenAPI documentation, and strict Pydantic data validation. I used SQLAlchemy ORM with MySQL for relational reliability and SQLite fallback support. For the frontend, I built a Single Page Application using React 18, Vite for instant HMR and optimized builds, and Tailwind CSS for a custom, responsive design system. For AI and parsing, I combined PyPDF2/pdfplumber/Tesseract OCR with the Google Gemini API."

Q3: "How does the resume parsing and matching algorithm work?"
A3: "When a resume is uploaded, the parser first attempts native text extraction using pdfplumber. If the resume is a scanned image, it automatically switches to Tesseract OCR to extract the text. The scoring algorithm then compares extracted candidate skills and years of experience against the job description. The composite score assigns 70% weight to skill match, 20% to experience alignment, and 10% to educational/domain context. This gives recruiters an accurate, deterministic match percentage."

Q4: "What happens if the Gemini AI service fails or hits rate limits?"
A4: "I implemented a resilient fallback architecture. If the Google Gemini API throws a 429 Rate Limit error or loses connectivity, the backend catches the exception and immediately falls back to an internal deterministic question generator. It crafts technical and scenario-based interview questions directly mapped to the candidate's matched and missing skills, ensuring 100% uptime."

Q5: "How is security handled across the application?"
A5: "Passwords are encrypted using one-way bcrypt hashing. API authentication is stateless using signed JWT bearer tokens. Every database query uses SQLAlchemy ORM parameterized queries to prevent SQL injection, and Pydantic schemas sanitize and validate all inbound payloads."

Q6: "How does the database handle scalability?"
A6: "The database uses normalized relational models with foreign key constraints and index lookups on frequently queried fields like candidate email, job status, and application stage. The architecture cleanly separates candidate profiles, resumes, job requisitions, and interviews so a single candidate can apply to multiple jobs without duplicate profile data."
